# AI가 운영을 맡은 방식

AI 해커톤이니 운영도 AI에게 많이 맡겼어요. 그렇다고 AI가 혼자 결정하게 두지는 않았어요. 기본 원칙은 **AI가 먼저 답하고, 사람은 같은 대화를 지켜보다가 판단이 필요한 것만 넘겨받는다**예요.

## 숫자로 보면 (2026-10-24, 디스코드 백업 기준)

| 항목 | 숫자 |
|---|---|
| 참가자 질문 | 65건. AI 첫 답까지 중앙값 31초, 80%(52건)가 2분 안 |
| 참가자방 봇 게시 | 205개: 질문 답변 72, 주제 선언 자동 게시 38, 결과 자동 발표 28, 제출 현황 4, 안내·공지 63 |
| 운영방(VC·운영진) 봇 게시 | 83개: VC 제출 알림 36, 샤크탱크 제안 알림 9, 주제 선언 현황 6, 입장 안내 7, 답변 6, 안내·넛지 19 |
| 판정 | 28건 모두 "먼저 3표" 규칙대로 자동. 운영진 수동 변경 0건 |
| 백업 | 5분마다 전체 상태 저장, 271회 |

## 1. 질문 응대: Claude Code가 운영 데스크

운영자 노트북에서 Claude Code 세션 하나가 하루 종일 디스코드를 지켰어요.

1. `ops/qna_watch.py`가 참가자방과 운영방(그리고 열린 스레드)을 20초마다 읽고, 사람이 쓴 새 질문을 한 줄씩 출력해요. 운영진 계정의 글은 건너뛰어요.
2. Claude Code는 이 출력을 백그라운드 모니터로 받아요. 새 줄이 오면 Claude가 깨어나 질문을 읽어요.
3. Claude는 `ops/faq.example.md`(그날의 사실·규칙·금지 사항을 적은 응대 기준)와 실시간 상태(`/api/state`)를 보고 답을 써요.
4. `ops/say.py`로 그 질문에 답글을 달아요. 모든 답 끝에는 **"Bloom Ops AI 답변이에요 · 운영진도 함께 보고 있어요"**가 붙어요. @everyone 같은 멘션은 막아 둬요.
5. 사람의 판단이 필요한 질문이면 Claude는 "운영진에게 확인할게요"라고 먼저 답하고, 운영자 휴대폰에 알림을 보낸 뒤 결정을 받아 같은 글에 이어 달아요.

응대 기준 파일에는 세 가지를 나눠 적어 두었어요.

- **사실**: 일정, 장소, 제출 방법, 규칙, 크레딧 사용법. 당일 결정이 생길 때마다 시각과 함께 추가했어요.
- **사람이 필요한 것**: 크레딧 미수령, 팀원 변경, 제출 실수 정정, 마감 예외 요청. AI는 접수만 하고 운영진에게 넘겨요.
- **절대 하지 않는 것**: 디스코드 글을 근거로 상태를 바꾸기(통과·탈락·리셋·팀 수정), 키나 심사 링크 공유, 공개 전 미션 내용 말하기, VC 개인 연락처 공유.

실제 장면 몇 개를 들면 이래요.

- 10:41 "STT나 TTS 같은 비LLM AI API를 써도 되나요?" → AI가 운영진 확인 후 10:45에 "변환용 API는 OK, 판단과 생성은 Claude로만"이라고 답했어요. 같은 내용을 공지로도 올렸어요.
- 10:52 "주제 선언 글이 글자 수 제한에 잘려요" → 서버의 제한을 바로 늘리고 10:53에 "아이디어 500자, 타깃 시장 300자로 늘렸어요. 같은 팀으로 다시 선언하면 덮어써져요"라고 답했어요.
- 14:59 "데모 사용법에 목데이터 안내를 더 넣고 싶어요" → 데모 사용법 칸을 1,500자로 늘리고 답했어요.
- 16:39 "PDF를 나중에 바꿀 수 있나요?" → "1차 심사용 PDF는 바꿀 수 없어요. 본선에 가면 다듬은 자료로 발표해도 돼요"라고 바로 답했어요.

## 2. 자동 게시: 사람이 누르지 않아도 흐르는 공지

서버와 운영 스크립트가 상태 변화를 보고 알아서 올렸어요.

| 무엇 | 어디로 | 하는 일 |
|---|---|---|
| 주제 선언 | 참가자방 | 팀이 선언하면 미션·아이디어·타깃·레포를 바로 게시 (서버 웹훅) |
| 새 제출 알림 | 운영방 | 제출이 들어올 때마다 VC 전원에게 @everyone (`ops/sub_ping.py`, 첫 제출은 `ops/first_sub.py`) |
| 결과 발표 | 참가자방 · LED | VC 3표가 모이면 즉시. 본선(PASS)은 제출 순서대로 발표해서 자리를 공정하게 채움 (`ops/autoreveal.py`) |
| 제출 현황 | 참가자방 | 지금 몇 팀 냈는지, 남은 본선 자리, 마감까지 남은 시간 (`ops/nudge.py`) |
| 주제 선언 현황 | 운영방 | 미션별로 어느 팀이 도전하는지 VC에게 정리 (`ops/topic_report.py`) |
| 샤크탱크 제안 | 운영방 | 콘솔에서 팀의 제안 받기를 열면 VC에게 한 번 알림 (`ops/offer_notify.py`) |
| 백업 | 로컬 파일 | 5분마다 전체 상태 저장 (`ops/backup.py`) |

결과 자동 발표는 처음부터 켠 게 아니에요. 오후 첫 결과가 쌓이기 시작한 15:16에 운영진 확인 단계를 없애고 자동으로 바꿨고, 15:24부터는 제출 순서대로 나가게 했어요. 늦게 낸 팀이 먼저 3표를 받아도 앞 팀 결과가 나올 때까지 LED에 "발표 대기"로 기다려요.

## 3. 행사 전날과 당일, AI가 만든 것

- **행사 전날**: 제출 페이지, VC 심사 화면, LED 보드, 실시간 현황, 운영 콘솔, 타이머, 디스코드 스크립트를 Claude Code로 만들었어요. 이 레포가 그 코드예요.
- **행사 중**: 위의 응대와 자동 게시 말고도, 규칙이 바뀔 때마다 화면과 서버를 그 자리에서 고쳤어요. 글자 수 확대, 자동 발표 전환, 발표 순서, 샤크탱크에서 VC 한 곳이 여러 팀과 매칭되게 바꾼 것(18:50) 같은 것들이에요.
- **행사 뒤**: VC 한 줄 평 아카이브(이름 없이 114개), VC별 결과 보고서, 감사 메일과 후속 미팅 연결 메일 초안. 보내는 건 사람이 확인하고 했어요.

## 4. 사람이 한 것

- 규칙과 예외를 정하는 일. 마감 연장, 패자부활 규칙, 매칭 방식 변경은 모두 운영진이 정했고, AI는 그 결정을 바로 공지·코드에 반영했어요.
- 무대 진행, VC와의 관계, 현장 동선.
- AI 답이 애매할 때 같은 글에 이어서 답하기. 참가자방에는 운영진도 늘 같이 있었어요.

## 따라 하려면

1. 디스코드 봇을 만들고 참가자방·운영방(VC와 운영진만 보이는 방)을 준비해요. `.env.example`의 디스코드 항목을 채워요.
2. `ops/faq.example.md`를 우리 행사에 맞게 고쳐요. "사람이 필요한 것"과 "절대 하지 않는 것"부터 정하는 게 좋아요.
3. 행사 날 운영자 노트북에서 Claude Code를 열고, `ops/qna_watch.py`를 백그라운드 모니터로 걸어 두라고 하세요. 응대 기준 파일을 읽고, 답은 `ops/say.py`로 달라고 알려 주면 돼요.
4. 자동 게시 스크립트(`sub_ping`, `autoreveal`, `nudge`, `backup` 등)는 따로 띄워 두거나 같은 세션에 맡겨요.
5. 결정이 생길 때마다 응대 기준 파일에 시각과 함께 한 줄씩 추가해요. AI가 같은 질문에 같은 답을 하게 돼요.
